## 🎬 TIPS UNTUK TAMPILAN BAIK

### Pembicara
1. **Pakaian:**
   - Gunakan warna solid atau stripe kecil (hindari polka/pattern kecil)
   - Warna yang kontras dengan background
   - Profesional tapi tidak formal berlebihan
   - Pastikan rapi dan nyaman

2. **Posisi & Gerakan:**
   - Duduk atau berdiri dengan posture tegak
   - Gunakan hand gesture untuk emphasis (jangan berlebihan)
   - Gerakkan head untuk variety, jangan diam seperti patung
   - Jarak ke camera: 0.5-1 meter
   - Pastikan wajah fully visible (crop properly)

3. **Kontak Mata:**
   - Lihat ke camera (tidak ke speaker lain)
   - Buat impression seperti berbicara ke penonton
   - Variasi antara notes/script dan camera eye contact

### Lingkungan & Background
1. **Background Options:**
   - Option A: Plain white/gray wall (professional)
   - Option B: Office/classroom background (contextual)
   - Option C: Virtual background (jika di rumah)
   - Hindari: Berantakan, distraktor visual yang kuat

2. **Lighting:**
   - **BAIK:** Cahaya dari depan atau samping (LED panel, ring light)
   - **BURUK:** Cahaya dari belakang (silhouette effect)
   - **OPTIMAL:** Soft light tanpa shadow keras di wajah
   - Tes dengan snip foto dulu

3. **Audio Environment:**
   - Recording di tempat yang quiet
   - Tutup pintu agar tidak ada noise eksternal
   - Jauh dari AC/fan yang berisik
   - Hindari carpet/hard floor yang create echo

## 🗣️ SPEAKING TIPS

### Intonasi & Rhythm
1. **Vary Your Tone:**
   - Jangan monoton
   - Naik-turun intonasi sesuai dengan content
   - Emphasize key points dengan infleksi
   - Gunakan pause untuk dramatic effect

2. **Speaking Pace:**
   - **Terlalu cepat:** Audience tidak bisa ikuti
   - **Terlalu lambat:** Boring, audience kehilangan focus
   - **IDEAL:** Kecepatan normal percakapan (120-150 wpm)
   - Lebih slow di technical section
   - Lebih cepat di bagian transisi

3. **Pronunciation:**
   - Clear articulation
   - Jangan menelan kata-kata
   - Latih pronunciation technical terms
   - Indonesian speakers: Hati-hati dengan 'r' dan 'l'

### Content Delivery
1. **Storytelling:**
   - Mulai dengan hook/attention grabber
   - Gunakan anekdot untuk humanize content
   - Build suspense (jangan reveal semua di awal)
   - Ending yang memorable

2. **Demo Narration:**
   - **NARRATE** apa yang Anda lakukan (jangan bisu)
   - "Sekarang saya klik tombol ini..."
   - "Lihat! Data sudah tersimpan..."
   - Beri waktu audience untuk proses visual

3. **Handling Technical Info:**
   - Simplify technical jargon jika possible
   - Define terms sebelum menggunakan
   - Gunakan analogi untuk complex concepts
   - Visual aids help (diagram, chart)

## 🎥 DEMO BEST PRACTICES

### Sebelum Recording Demo

1. **Data Setup:**
   ```
   ✓ Clear browser cache
   ✓ Populate demo data (users, journals, etc)
   ✓ Test login dengan semua account type
   ✓ Buat sample data untuk ditampilkan
   ✓ Practice mouse click sequence
   ✓ Know exactly where to click
   ```

2. **Browser Setup:**
   ```
   ✓ Zoom: 100% (tidak terlalu besar/kecil)
   ✓ Full screen browser
   ✓ Bookmarks bar hidden
   ✓ No other tabs open (distraction)
   ✓ Cursor visible (jangan invisible)
   ✓ Dark mode atau light mode? (chose one)
   ```

3. **Demo Timing:**
   ```
   - Keep each demo segment SHORT (1-2 min max)
   - If demo is long, break into multiple clips
   - Add transition between demo clips
   - Have backup screenshot jika demo gagal
   ```

### Saat Recording Demo

1. **Mouse Movement:**
   - **SLOW & DELIBERATE** — audiens harus bisa lihat
   - Jangan "teleport" cursor tiba-tiba
   - Small movements itu ok, big jumps buruk
   - Point sebelum click untuk emphasis

2. **Clicking:**
   - Tunggu 0.5 detik setelah click untuk load
   - Jangan rapid-click (looks unprofessional)
   - Highlight hasil action dengan penjelasan

3. **Form Filling:**
   - Type "naturally" (bukan instan)
   - Baca fields saat diisi
   - Show validation working
   - Demo both valid dan invalid input

4. **Common Demo Mistakes:**
   ```
   ❌ Terlalu cepat (audience tidak bisa ikuti)
   ❌ Terlalu lama (audience bosan)
   ❌ Berbisik atau silent saat demo
   ❌ Klik di tempat yang salah & harus undo
   ❌ Browser crash atau timeout
   ❌ Typo dalam form yang tidak di-clear
   ```

## 🤝 KOORDINASI UNTUK 2 PEMBICARA

### Role Clarity
```
PEMBICARA 1 (P1):
├─ Opening & Perkenalan
├─ Teknologi & Architecture
├─ Authentication flow
├─ Challenges & Lessons
└─ Demo bagian tertentu

PEMBICARA 2 (P2):
├─ Latar belakang & Tujuan
├─ Penjelasan 4 modul
├─ Demo modul utama
├─ Testing & QA
├─ Kesimpulan
└─ Q&A handling
```

### Koordinasi Teknis
1. **Hand-off smoothly:**
   - P1: "...dan sekarang saya serahkan ke [Nama P2]"
   - P2: "Terima kasih, [Nama P1]. Sekarang mari kita lihat..."
   - JANGAN: Tiba-tiba cut ke pembicara lain

2. **Screen Sharing:**
   - Option A: P1 screen record full, voice over untuk P2
   - Option B: Edit video post-production (split screen, PIP)
   - Option C: Record terpisah lalu composite
   - BEST: Screen + slide presentation di bawah

3. **Timing Sync:**
   - Buatkan timeline dengan exact timing
   - P1: 0:00-2:30, P2: 2:30-5:00, P1 Demo: 5:00-7:00, etc
   - Build in buffer time untuk natural pauses
   - Total durasi target: 10-15 menit

### Recording Strategy
```
OPTION 1: Full Continuous Recording
├─ Record satu long take
├─ Minimal editing required
├─ Perlu banyak rehearsal
└─ Riskio: Kesalahan = redo full video

OPTION 2: Segment Recording
├─ Record per segment (1-2 min)
├─ Easier untuk fix mistakes
├─ Lebih fleksibel dengan demo
└─ Lebih banyak editing work

RECOMMENDATION: Hybrid
├─ Record full video untuk flow
├─ Re-record segments yang salah
├─ Composite dalam editing
└─ Balance antara quality & effort
```

## ✂️ EDITING TIPS (Post-Production)

### Essentials
1. **Intro/Outro:**
   - 3-5 second intro (title card)
   - 2-3 second outro (thank you)
   - Add music if appropriate

2. **Transitions:**
   - Simple fade/dissolve (tidak flashy)
   - 0.5-1 second duration
   - Between major section changes
   - Avoid every-slide transition (annoying)

3. **Graphics & Text:**
   - Add "chapter markers" (0:00 - Intro, 2:30 - Demo, etc)
   - Highlight key points dengan text overlay
   - Add timestamp saat menunjuk ke bagian tertentu
   - Label modul/feature yang ditampilkan

### Color & Grading
- Consistent color temperature
- Proper exposure (tidak terlalu terang/gelap)
- White balance (jangan blue cast atau yellow cast)
- Saturation moderate (tidak oversaturated)

### Audio
- Normalize volume (consistent throughout)
- Remove background noise jika ada
- Sync audio dengan video properly
- Add subtle background music if needed
- Subtitle untuk accessibility ✓

### File Output
- **Format:** MP4 (H.264) atau WebM
- **Resolution:** 1080p minimum (1440p better)
- **Bitrate:** 5-8 Mbps (good quality)
- **Frame rate:** 30fps atau 60fps
- **Codec:** H.264 (compatibility)

## 📝 SCRIPT NOTATION

Gunakan notasi ini saat menulis/mempraktekan script:

```
[SLOW] = Berbicara lebih lambat
[PAUSE] = Diam 1-2 detik untuk effect
[POINT] = Gesture ke arah sesuatu
[LOOK AT CAMERA] = Eye contact
[EMPHASIZE] = Nada lebih kuat

VISUAL: [Slide 3] = Switch ke visual/slide 3
DEMO: Click "Login button" = Saat demo klik ini
SPEAKER CHANGE: → P2 = Ganti pembicara
TIMING NOTE: (00:45) = Checkpoint timing
```

### Contoh Script Annotated:
```
P1:
"Assalamu'alaikum, semuanya. [LOOK AT CAMERA]
Nama saya [Nama P1]. [PAUSE]

Hari ini kami akan memperlihatkan hasil proyek kami
yang bernama [EMPHASIZE] SIS-TERPADU.

Ini adalah sistem manajemen sekolah terintegrasi...
[SLOW - biar paham maksud]
...yang dirancang untuk memudahkan guru dan admin.

[POINT TO SCREEN]
VISUAL: [Slide 2 - Dashboard screenshot]
Mari kita lihat tampilan aplikasinya.

[PAUSE]
Sebelum itu, izinkan saya serahkan kepada [Nama P2]
untuk memberikan latar belakang proyek ini.

→ P2 [TIMING: 01:30]
"
```

## ❓ HANDLING Q&A

### Preparation
```
Anticipated Questions:

Q1: "Bagaimana cara deploy aplikasi ini?"
A: [Prepare jawaban - mention future plans]

Q2: "Apakah bisa di-integrate dengan sistem existing?"
A: [Discuss architecture & API design]

Q3: "Berapa cost untuk development?"
A: [Prepare project estimation]

Q4: "Apakah bisa offline?"
A: [Explain IndexedDB capability]

Q5: "Bagaimana keamanan data?"
A: [Explain authentication & authorization]
```

### Q&A Best Practices
1. **Listen fully** sebelum jawab
2. **Repeat question** jika kurang jelas
3. **Think before answer** (jangan terburu)
4. **Be honest** jika tidak tahu (not a shame)
5. **Keep answer concise** (jangan panjang)
6. **Ask for clarification** jika perlu
7. **Follow up** dengan "Does that answer help?"

## 🚨 BACKUP PLANS

### If Demo Fails During Recording:
```
PLAN A: Screenshot fallback
├─ Siapkan screenshot dari setiap step
├─ Use screenshot saat live demo gagal
├─ Narrate "ini adalah hasilnya" sambil tunjuk SS
└─ Edit video jadi smooth

PLAN B: Re-record segment
├─ Pause, fix issue, re-do that section
├─ Edit splice dengan yang lain
├─ Viewer tidak akan tahu ada kesalahan

PLAN C: Scripted demo
├─ Jangan live demo, use recorded video
├─ Narrate over pre-recorded demo video
├─ Paling reliable tapi kurang spontan
```

### If Audio Fails:
```
PLAN A: Re-record audio only
├─ Keep video, re-record just audio track
├─ Sync dalam editing

PLAN B: Use transcript + text-to-speech
├─ Last resort
├─ Add captions dari audio original

PLAN C: Record ulang full segment
├─ Sometimes necessary
```
